Linux 内核社区热点与趋势

Linus Torvalds 明确表示 Linux 内核不会采取「反 AI」立场
针对社区内部分开发者对 AI 和大语言模型（LLM）进入内核开发的抵触情绪，Linus Torvalds 近期发表评论称，Linux 项目不会成为那些盲目反对 AI 的项目之一。他强调 Linux 内核开发应保持务实，只要 AI 生成的代码或补丁符合现有的质量标准和审查流程，就不应被排斥。这一表态旨在平息社区争论，并为未来探索 AI 辅助内核开发工具留出空间。

io_uring 引入无锁 MPSC FIFO 队列显著提升性能
在即将发布的 Linux 7.2 内核中，io_uring 子系统将弃用传统的内核链表原语，转而采用一种新的无锁多生产者单消费者（MPSC）队列。这一改进旨在解决高并发场景下的锁竞争问题，使 io_uring 在处理大量异步任务时更加高效。初步测试显示，该优化带来了显著的性能增益，展示了复杂无锁算法在高性能 I/O 框架中的应用潜力。
原文：Lockless MPSC FIFO queues for io_uring

Linux 维护者 Greg Kroah-Hartman 谈 Rust 带来的编程乐趣
长期担任 Linux 稳定版维护者的 Greg Kroah-Hartman 在近期采访中表示，Rust 语言正在让系统级编程重新变得有趣。他指出，Rust 的内存安全特性不仅减少了常见的 C 语言漏洞，还改变了开发者的思维方式，使内核开发更加现代化。尽管 C 语言仍是核心，但 Rust 在驱动程序和子系统中的应用正稳步推进，成为 Linux 演进的重要方向。

TuxBot：利用大语言模型进行在线操作系统调优

MARS：面向大数据量缓冲读取的多阶段加速读取栈
研究人员针对现代高速存储设备提出了 MARS 架构，旨在优化 Linux 的缓冲读取（Buffered Read）性能。MARS 将大范围读取视为单一工作单元，并通过数据结构对页面缓存操作进行分阶段处理，减少了系统调用开销和元数据竞争。该研究成功解决了 Linux 在利用并行 SSD 处理大数据量读取时无法充分暴露 I/O 并发性的痛点。
原文：MARS: Multi-stage Accelerated Read Stack for Large-buffer Buffered Reads

OriginBlame：AI 训练数据集的记录级与令牌级数据溯源
针对 AI 模型「去学习」（Unlearning）的需求，OriginBlame 提出了一种精确的数据溯源系统。该系统可以在复杂的数据处理流水线中追踪作者身份，精确到记录甚至令牌级别。实验证明，这种方法能将数据集的过度删除率从 101 倍降低到 1.3 倍，同时仅增加极低的吞吐量开销，为版权保护和数据撤回提供了技术支撑。
