Linux 7.2-rc3 发布：开发节奏进入“新常态”
Linus Torvalds 发布了 Linux 7.2 的第三个候选版本，标志着该版本向 8 月份的稳定版迈进。Linus 指出，目前的提交率略高，但整体处于一种“新常态”，部分原因可能是夏季假期导致的工作节奏波动。此版本包含了大量针对驱动程序和架构的常规修复。

Linux 7.2 默认支持 UltraRISC RISC-V 架构
继支持 Eswin SoC 之后，Linux 7.2 内核现在将 UltraRISC 架构的支持纳入了 RISC-V 的默认构建配置（defconfig）。这意味着开发者和用户在构建标准 RISC-V 内核时，将直接获得该国产 RISC-V 芯片的兼容性。这一举措进一步扩大了 Linux 对新兴 RISC-V 硬件生态的覆盖范围。

Realtek RTL8723BS WiFi 驱动加固，防御恶意接入点攻击
在 Linux 7.2-rc3 中，开发者针对 Realtek RTL8723BS WiFi 驱动进行了安全加固，修复了多个潜在的越界访问漏洞。这些漏洞可能在连接到“恶意”WiFi 主机时被触发，导致系统崩溃或被利用。此次更新体现了内核社区对老旧硬件驱动在现代网络环境下安全性持续维护的重视。

OpenSSH 10.4 发布，强化 Linux 沙盒安全要求
OpenSSH 10.4 正式发布，引入了实验性的后量子加密签名方案（ML-DSA 44 与 Ed25519 结合）。在 Linux 系统上，如果编译时启用了沙盒支持，新版本将强制要求系统开启 SECCOMP 或 NO_NEW_PRIVS，否则 sshd 将无法运行。这一变化显著提升了 SSH 服务在 Linux 环境下的安全隔离强度。

学术界最新研究

StickyMoE：通过路由一致性损失实现内存高效的 MoE 推理
针对混合专家模型（MoE）在边缘设备上频繁切换专家导致的权重交换开销，研究者提出了 StickyMoE。该方法在预训练中引入可微的路由一致性损失，惩罚相邻 Token 之间的专家切换，鼓励模型在语义连贯的片段内保持专家分配。实验表明，这种方法在不改变架构的情况下显著降低了推理时的内存带宽压力。
原文：Sticky Routing: Training MoE Models for Memory-Efficient Inference

Director：通过在线主动专家放置加速分布式 MoE 服务
由于 MoE 模型的专家激活模式随请求动态变化，传统的静态放置策略难以维持最优性能。Director 框架提出了一种在线、主动的专家放置算法，能够根据实时流量预测和迁移成本优化 GPU 间的专家分布。该研究解决了专家并行模式下的通信瓶颈，显著提升了分布式推理的吞吐量。
原文：Director: Accelerating Distributed MoE Serving via Online Proactive Expert Placement

KV-PRM：利用 KV 缓存转移实现高效的过程奖励模型
过程奖励模型（PRM）在引导多代理系统推理时效果显著，但传统的文本重编码方式计算成本极高。KV-PRM 通过直接读取 LLM 生成阶段产生的 KV 缓存来消除重复编码，将评分成本从序列长度的平方级降低。这一改进使得 PRM 能够应用于长上下文场景，大幅提升了多代理系统的测试时扩展效率。
